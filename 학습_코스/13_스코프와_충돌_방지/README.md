# 13. 스코프와 충돌 방지

## 학습 목표

- 전역 Core 단어와 Library Pack 단어의 적용 범위를 구분합니다.
- 실제 import가 팩을 활성화하는 이유를 이해합니다.
- 직접 import, 별칭, 메서드, 키워드 인자, shadowing을 실험합니다.
- 현재 구현이 보장하는 범위와 남은 한계를 구분합니다.

## 충돌이 생기는 이유

`add`, `get`, `run`, `search`처럼 흔한 이름은 여러 라이브러리와 사용자 객체가 공유합니다. 이를 전역 치환하면 전혀 관계없는 코드가 바뀝니다. KoPy는 실제 import를 분석해 관련 팩을 활성화합니다.

```kopy
임포트 넘파이 애즈 np
배열 = np.어레이([1, 2])
```

위 코드에서는 `어레이 → array`가 적용됩니다. 반면 NumPy import 없이 작성한 `np.어레이`를 KoPy가 임의로 추측해 바꾸지 않습니다.

## 구분해야 할 문맥

- 실제 모듈 import 경로
- `module.member` 속성 접근
- `from module import member` 직접 import
- 함수 호출의 `name=value` 키워드 인자
- 함수 매개변수와 지역 변수
- 모듈 수준의 재할당으로 생기는 shadowing

`top_k`는 검색·추천·ML에서 원문 자체를 익힐 가치가 큰 명시적 교육 예외이므로 현재 영어 형태를 유지합니다.

## 현재 한계도 숨기지 않는다

현재 0.5.51의 팩 전용 키워드 인자는 **팩이 import된 파일의 함수 호출 키워드 위치**에서 변환됩니다. 그러나 모든 경우에 정확한 호출 대상까지 식별하는 것은 아닙니다. 예를 들어 PEFT를 import한 뒤 관계없는 함수에 `로라_알파=`를 쓰면 현재 구현은 `lora_alpha=`로 바꿉니다.

이는 보장된 최종 설계가 아니라 추가적인 callee-specific 스코핑이 필요한 한계입니다. 학습 자료와 테스트는 현재 사실을 기록하며, 구현이 개선되면 함께 갱신해야 합니다.
