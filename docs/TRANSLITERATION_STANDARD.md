# KoPy 음역 표준

KoPy의 기본 원칙은 **영어 Python 표현을 한글로 음역하면서 원문 Python과의 대응 관계를 잃지 않는 것**입니다. 한국어로 의미를 번역하는 언어가 아니라, 영어 코드를 읽고 쓰는 감각을 단계적으로 익히게 하는 학습 레이어입니다.

## 1. 기본 원칙

1. 영어 식별자와 API 이름은 가능한 한 발음에 가까운 한글 음역을 제공합니다.
2. 원문에 포함된 숫자는 읽어서 한글로 풀지 않고 **숫자 그대로 유지**합니다.
3. 원문의 언더스코어 구조는 유지합니다.
4. 문자열, 주석, 데이터 값은 음역하지 않습니다.
5. Library Pack 고유 API와 일반적인 메서드 이름은 해당 pack 안에서 namespace-scoped로 음역할 수 있습니다.
6. 여러 라이브러리에서 반복되는 공통 학습 식별자는 별도의 공통 식별자 레지스트리에서 양방향 변환합니다.
7. 원문을 그대로 익힐 교육 가치가 특히 큰 표준 인자는 예외적으로 영어를 유지할 수 있으며, 그 이유를 문서에 설명합니다.
8. KoPy 음역과 원문 Python은 같은 파일에서 혼용할 수 있어야 하며, 음역을 추가해도 기존 Python 코드를 깨뜨리지 않습니다.

## 2. 숫자는 그대로 유지

잘못된 형태:

```text
BM25        -> 비엠이십오
F1Score     -> 에프원스코어
IndexFlatL2 -> 인덱스플랫엘투
gaussian_blur2d -> 가우시안블러투디
```

표준 형태:

```text
BM25        -> 비엠25
F1Score     -> 에프1스코어
IndexFlatL2 -> 인덱스플랫엘2
gaussian_blur2d -> 가우시안_블러2디
```

숫자의 의미를 해석하거나 읽는 것이 아니라 **원문 토큰의 형태를 보존**하는 것이 기준입니다.

## 4. 일반 메서드도 pack 안에서는 음역한다

`add`, `search`, `retrieve`, `run`, `get`처럼 여러 라이브러리에서 재사용되는 이름을 **전역** 음역하면 의미 충돌이 생길 수 있습니다. 그렇다고 영어로 방치하는 것이 KoPy의 기본 정책은 아닙니다.

KoPy 0.5.48부터 이런 이름은 가능한 경우 해당 Library Pack 안에서만 음역합니다.

```kopy
# FAISS가 활성화된 경우
인덱스.애드(임베딩즈)
디스턴시즈, 인디시즈 = 인덱스.서치(쿼리, 2)

# BM25S가 활성화된 경우
리절츠 = 리트리버.리트리브(쿼리_토큰즈, k=5)

# Chroma가 활성화된 경우
컬렉션.업서트(아이디즈=아이디즈, 임베딩즈=임베딩즈)

# Haystack이 활성화된 경우
파이프라인.애드컴포넌트("retriever", 리트리버)
리절트 = 파이프라인.런(인풋)
```

해당 pack을 import하지 않은 코드에서는 `서치`, `리트리브`, `업서트`, `런`을 임의로 Python 이름으로 추측하지 않습니다. 이것이 **음역 우선 + 충돌 방지**의 기준입니다.

## 5. `top_k`를 유지하는 이유

`top_k`는 검색·추천·머신러닝 코드에서 매우 자주 등장하는 표준 표현입니다. `k`는 상위 몇 개를 선택할 것인가를 나타내며 논문과 여러 Python 라이브러리에서 거의 같은 형태로 반복됩니다.

```kopy
리트리버 = 인메모리비엠25리트리버(
    다큐먼트_스토어=다큐먼트_스토어,
    top_k=2,
)
```

이 예외는 영어를 남기는 것이 기본이라는 뜻이 아닙니다. **기본은 음역이고, 명시적으로 교육 가치가 높은 표현만 예외로 남깁니다.**

## 6. 공통 RAG 식별자와 키워드 인자

0.5.49부터 충돌 위험이 낮고 여러 RAG 팩에서 반복되는 이름은 공통 음역 대상으로 확대합니다. 0.5.50에서는 ML/RAG 예제에 반복적으로 등장하는 시그니처 키워드 인자까지 같은 원칙으로 확장합니다.

```kopy
클라이언트 = 크로마.클라이언트()
컬렉션 = 클라이언트.크리에이트컬렉션(
    네임="docs",
    임베딩_펑션=논,
)
리절트 = 컬렉션.쿼리(
    쿼리_임베딩즈=임베딩즈,
    엔_리절츠=2,
)
```

`query_embeddings=`, `n_results=`, `show_progress=`, `test_size=`, `random_state=`, `max_iter=`, `dtype=`처럼 함수 호출 시 키워드 인자로 쓰이는 이름도 Python tokenizer에서는 식별자 토큰이므로 같은 양방향 공통 음역 규칙으로 처리할 수 있습니다. 실제 라이브러리 시그니처와 정확히 다시 연결되어야 하므로 테스트를 반드시 둡니다.

숫자와 문자열 값은 번역하지 않습니다. 예를 들어 `테스트_사이즈=0.2`, `랜덤_스테이트=42`, `디타입="float32"`는 각각 `test_size=0.2`, `random_state=42`, `dtype="float32"`로 돌아갑니다.

`top_k`는 이 범주에 넣지 않습니다. 교육적 이유로 원문을 남기는 명시적 예외입니다.

## 7. Library Pack과 공통 식별자의 경계

```kopy
임포트 파이스 애즈 faiss
인덱스 = faiss.인덱스플랫엘2(384)
인덱스.서치(쿼리, 5)
```

여기서 `인덱스`는 공통 식별자 `index`, `인덱스플랫엘2`는 FAISS 전용 `IndexFlatL2`, `서치`는 FAISS pack 안에서만 활성화되는 `search`입니다. 서로 다른 층으로 처리해 충돌을 줄입니다.

## 8. 문서와 예제 작성 규칙

- 사용자 변수명을 이유 없이 영어로 방치하지 않습니다.
- API가 영어로 남아 있다면 실제로 음역할 수 없는 이유 또는 교육적 예외인지 검토합니다.
- 숫자 포함 이름은 숫자를 그대로 유지합니다.
- 원문 Python 예제를 함께 보여 주어 음역과 원문의 대응 관계를 학습할 수 있게 합니다.
- 라이브러리의 실제 dotted import 경로는 필요하면 그대로 유지합니다. 경로 구조 자체도 Python 학습 대상이기 때문입니다.
- 키워드 인자는 함수 시그니처와 직접 연결되므로 전 팩 충돌 감사를 거쳐 단계적으로 음역합니다.
