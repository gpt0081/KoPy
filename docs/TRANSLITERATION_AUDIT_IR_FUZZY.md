# IR·fuzzy search 음역 감사

KoPy의 기본은 영어 식별자·API·키워드 인자를 한글로 음역하는 것입니다. 숫자와 문자열 값은 그대로 유지하고, 실제 Python dotted import 경로는 학습 가치가 있으므로 필요할 때 보존합니다.

이번 감사에서는 검색·평가 코드에 반복적으로 남아 있던 표현을 공통 양방향 음역 대상으로 올립니다.

| Python | KoPy |
| --- | --- |
| `runs` | `런즈` |
| `method` | `메서드` |
| `norm` | `노름` |
| `metric` | `메트릭` |
| `qrels` | `큐렐즈` |
| `scorer` | `스코어러` |
| `processor` | `프로세서` |
| `score_cutoff` | `스코어_컷오프` |
| `limit` | `리밋` |
| `candidate` | `캔디데이트` |
| `dense_run` | `덴스_런` |
| `lexical_run` | `렉시컬_런` |
| `hybrid_run` | `하이브리드_런` |

ranx의 `evaluate`와 `compare`, RapidFuzz의 `fuzz`와 `process`도 각 Library Pack 안에서 음역합니다. 일반 API를 전역 추측으로 바꾸지 않고, 해당 팩이 import된 경우에만 라이브러리 고유 이름을 해석합니다.

`metric`/`qrels`처럼 일반 식별자의 음역이 `Metric`/`Qrels` 같은 직접 import 클래스의 음역과 같아질 수 있습니다. KoPy translator는 함수 매개변수, 반복문 target, `with ... as`, 예외 이름, 기타 Python local binding을 확인해 그 함수 스코프에서는 일반 식별자가 우선하도록 처리합니다. 따라서 `프롬 랜엑스 임포트 큐렐즈`와 `데프 load(큐렐즈): ...`를 함께 써도 import는 `Qrels`, 매개변수와 함수 본문은 `qrels`로 복원됩니다.

`score`는 이번 공통 레지스트리에는 넣지 않습니다. 변수명으로도 흔하지만 scikit-learn, Ragas 등 여러 라이브러리의 `.score()` 메서드와 충돌할 수 있기 때문입니다. 일반 식별자와 라이브러리 메서드를 안전하게 구분할 수 있는 문맥이 있을 때만 이후 단계에서 다룹니다.

예:

```kopy
프롬 랜엑스 임포트 퓨즈, 이밸류에이트

하이브리드_런 = 퓨즈(
    런즈=[덴스_런, 렉시컬_런],
    노름="min-max",
    메서드="sum",
)
리절트 = 이밸류에이트(큐렐즈, 하이브리드_런, "ndcg@3")
```

```kopy
프롬 래피드퍼즈 임포트 퍼즈, 프로세스

베스트 = 프로세스.익스트랙트원(
    쿼리,
    초이시즈,
    스코어러=퍼즈.더블유레이쇼,
    스코어_컷오프=50,
)
```

`process.extractOne`은 최상위 1개 결과를 반환하므로 `limit` 인자를 받지 않습니다. 여러 결과가 필요하면 `프로세스.익스트랙트(..., 리밋=3)`를 사용합니다. 숫자 `50`, `3`과 문자열 `"sum"`, `"ndcg@3"`은 데이터 값이므로 음역하지 않습니다. `top_k`는 검색·추천·ML 원문에서 반복되는 교육적 표준 표현이라는 기존의 명시적 예외를 유지합니다.
